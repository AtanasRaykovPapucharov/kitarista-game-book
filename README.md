# Китариста – „Докато слушаш звездите“

[![Check](https://github.com/AtanasRaykovPapucharov/kitarista-game-book/actions/workflows/check.yml/badge.svg)](https://github.com/AtanasRaykovPapucharov/kitarista-game-book/actions/workflows/check.yml)

Книга-игра (Quasar + Vue 3 + Pinia + vue-i18n) по разказа на Атанас Папучаров: момче получава китара – и глас от дълбините на космоса. Оригиналните инструменти на Китариста (компас, тюнер, акорди, гами…) са запазени в меню „Репетиционна“.

```bash
npm install
npm run dev      # http://localhost:9000
npm run build    # dist/spa
```

## Правила (по модела на Fighting Fantasy)

| Качество    | Начало   | Роля                                                            |
| ----------- | -------- | --------------------------------------------------------------- |
| Майсторлък  | 1d6 + 6  | проверки (2d6 ≤ стойност) и атака в дуели                       |
| Вдъхновение | 2d6 + 12 | „живот“; при 0 – финал „Тишина“                                 |
| Късмет      | 1d6 + 6  | проверки; всеки опит го намалява с 1                            |
| Мрак        | 0        | колко от теб принадлежи на гласа; усилва сенките, затваря врати |

Дуел: всеки рунд 2d6 + Майсторлък срещу 2d6 + Майсторлък на противника. Губещият рунд губи 2 точки. След рунд може да се изпробва Късметът. Дуелът се губи след определен брой загубени рундове. Изпълнените мисии от Репетиционна отключват „музикален ход“: въпрос от наученото (акорди, интервали, гами, настройване), който дава +3 към атаката при верен отговор и −1 при грешен.

166 секции, 5 финала, 10 дуела, 26 проверки, 5 урока, 11 вещи, 7 мисии, 6 упражнения на истинската китара, 30 постижения и 18 илюстрации. Номерата на секциите се разбъркват с фиксиран seed, както в печатна книга.

## Структура

```
src/story/book.js            механиката: секции, избори, проверки, зарове, дуели, финали
src/story/items.js           вещи (икона, бонус в дуел, ефект при използване)
src/story/content/bg.js|en.js  текстът на двата езика (същите ключове като book.js)
src/game/engine.js           чисти функции върху save обекта (зарове, ефекти, дуели)
src/game/useStory.js         текст за текущия език + {counter} и условни абзаци
src/game/sound.js            китарни звуци чрез src/components/music/guitarSynth.js
src/stores/auth-store.js     локални профили (регистрация, вход, изход, изтриване)
src/stores/game-store.js     един save на потребител + профил с открити финали
src/services/storage.js      единственото място, което пише в localStorage
src/components/game/*        зарове, проверки, дуел, избори, лист на приключението
src/pages/*Page.vue          корица, вход, регистрация, герой, игра, правила, профил
```

### Как се добавя секция

1. В `book.js` добави ключ, напр. `rooftop: { choices: [{ id: 'jump', to: 'x' }] }`.
2. Добави `rooftop: { title, text: [...], choices: { jump: '...' } }` в `content/bg.js` и `content/en.js`.
3. Пусни симулацията (по-долу), за да провериш за липсващ текст и задънени улици.

Абзац може да бъде условен: `{ ifFlag: 'viktoria_comes', text: '...' }`, `{ ifNotFlag }`, `{ ifItem }`. В заглавия и текст `{day}` се заменя със стойността на брояча.

Родови форми: `[мъжки|женски|среден]`, напр. `колко си [пораснал|пораснала|пораснало]`. При регистрацията потребителят избира Момче, Момиче или Друг; при „Друг“ въвежда име на пола и желано обръщение (мъжки, женски или среден род), а историята използва съответната форма. Всичко се сменя от Профил. Ако липсва форма, се взима първата. Профили отпреди тази промяна се четат като момче.

## Данни и сигурност

Засега всичко е в localStorage на браузъра. Паролите са солени и хеширани (SHA-256 през Web Crypto, което изисква https или localhost), но това **не е истинска защита**: всеки с достъп до браузъра може да прочете данните. За реални потребители замени действията в `auth-store.js` и ключовете в `storage.js` с API заявки.

Ключове: `kitarista-users`, `kitarista-session`, `kitarista-save:<id>`, `kitarista-profile:<id>`, `kitarista-locale`, `kitarista-sound`.

## Езици

Само `bg` и `en-US`. Интерфейсът е в `src/i18n/*`, историята е в `src/story/content/*`.

## Проверки

При всеки push GitHub Actions (`.github/workflows/check.yml`) пуска:

- `eslint` – грешки в кода;
- `npm run check-story -- 5000` – всяка секция е достижима, няма задънени улици, текстът е пълен на двата езика, изданието на „вие“ е актуално, мисиите и картинките са на място (игрите са детерминирани: `CHECK_SEED=123 npm run check-story` пробва други);
- `npm run build`.

Ако проверката падне, в GitHub се вижда червен ✗ и в лога пише точно какво не е наред. Най-честата причина след промяна в българския текст: забравено `npm run make-plural`.
